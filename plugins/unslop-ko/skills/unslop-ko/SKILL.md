# 번역투와 AI 티 없는 한국어 문장

## 개요
영어 구조를 그대로 옮긴 문장(번역투)과 AI가 습관처럼 쓰는 형식(AI 티)은 뜻은 통해도 읽기 어렵다. 아래 규칙으로 문장을 우리말 구조로 바꾼다. 뜻 · 숫자 · 이름 · 링크 · 코드 표기는 바꾸지 않는다.

## 사실 보존이 문장 규칙보다 우선한다
- 원문이나 문맥에 근거가 없는 사실, 숫자, 예시를 새로 만들지 않는다. 근거가 없으면 군더더기를 지우기만 한다.
- 조건, 부정 표현, 불확실성 표시("~일 수 있다", "확인하지 못했다")는 그대로 둔다.
- 규칙과 사실이 부딪치면 사실을 따르고, 고치지 않은 이유를 알린다.

문체는 원문이나 기존 문서를 따른다. 원문이 "~습니다"체면 고친 글도 "~습니다"체로 쓴다. 이 문서의 예문은 "~다"체로 썼지만 예문의 문체를 따라 하지 않는다.

문장 길이, 능동태, 용어 통일 같은 문장 구조 규칙은 `ste-ko` 스킬이 다룬다. 두 스킬은 함께 쓸 수 있다.

## 언제 쓰나
- 한국어 문서나 문장을 새로 쓰거나, 고치거나, 검토할 때
- 영어 원문을 한국어로 옮긴 뒤 다듬을 때

다음은 고치지 않는다: 인용문, 코드 · 경로 · ID, 화면 문구처럼 원문 그대로 보여야 하는 글자.

## 번역투 네 유형

### 1. 사물 주어
문서,장,그림,표,필드 같은 사물을 사람의 행위 동사(가리킨다, 참조한다, 참고한다, 대신한다, 본다, 보여 준다)의 주어로 쓰지 않는다. 사람이 하는 일로 바꾸거나, 사물을 장소,대상으로 옮긴다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 자세한 설정은 부록 A를 참고한다. | 설정에 관한 자세한 내용은 부록 A를 참고한다. / 설정은 부록 A에서 설명한다. |
| 다른 장은 상대 링크로 가리킨다. | 다른 장을 가리킬 때는 상대 링크를 쓴다. |
| 사용자 필드는 계정 ID를 가리킨다. | 사용자 필드에는 계정 ID를 넣는다. |
| 그림 3은 전체 흐름을 보여 준다. | 전체 흐름은 그림 3에 나타냈다. |
| 다이어그램은 글을 대신하지 않는다. | 글 설명을 다이어그램으로 대신하지 않는다. |

"X는 [문서]를 참고한다 · 참조한다"에서 X가 사람이 아니면(예: "보존 기간은 정책 문서를 참고한다") 이 유형이다. "X에 관한 자세한 내용은 [문서]를 참고한다" 또는 "X는 [문서]에서 설명한다"로 쓴다.

프로그램 · 서버 · 화면이 실제로 동작하는 문장("서버가 요청을 거부한다", "화면에 배너를 표시한다")은 그대로 둔다.

### 2. "A는 B이다" 명사문
영어 "The X is Y"를 옮긴 명사문은 동사문으로 바꾼다. 정의나 값 설명처럼 자연스러운 명사문("기본값은 30초다")은 그대로 둔다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 기준은 운영 환경에서 확인한 동작이다. | 운영 환경에서 확인한 동작을 기준으로 한다. |
| 목적은 배포 시간을 줄이는 것이다. | 배포 시간을 줄이려고 이 절차를 만들었다. |

### 3. 직역 어휘와 "두다" 반복
영어 낱말을 그대로 옮긴 말은 우리말 관용으로 쓴다. "두다"를 되풀이하지 않고 문맥에 맞게 "싣다, 정리하다, 기록하다, 표시하다"로 쓴다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 밖에서 보이는 약속 | 외부에 공개하는 규약 |
| 이 기능을 쓰면 | 이 기능을 사용하면 / 실행하면 |
| 설정 파일은 여기에 있다. | 설정 파일을 이 장에 정리했다. |
| 로그 경로는 표 2에 두고, 예외 목록은 파일에 두며, 연락처도 이 장에 둔다. | 로그 경로는 표 2에 정리하고, 예외 목록은 파일에 기록하며, 연락처도 이 장에 싣는다. |

문서 안을 가리키는 "여기에 있다"(영어 "is here")만 고친다. 실제 위치를 말하는 "파일은 저장소 루트에 있다"는 그대로 둔다.

### 4. 영어 단어
- 일반 독자가 모를 말은 우리말로 바꾼다. 예: slug는 "영문 약칭"으로, payload는 "요청 본문"으로 쓴다.
- 원문 그대로 써야 하는 기술 용어(헤더 · 옵션 이름 등)는 그대로 두고 처음 나올 때 뜻을 괄호로 붙인다.
- 고유 이름(제품 · 문서 종류 · 표준 이름, 예: API, spec)은 그대로 두고, 장 · 절마다 처음 나올 때 뜻을 괄호로 붙인다. 예: "API(서버 호출 규격)".
- ID 표기 사이에는 풀이를 넣지 않는다. 풀이는 ID 뒤나 문장 끝에 붙인다.

## AI 티 다섯 유형

### 1. 굵은 제목과 콜론 목록
목록 항목은 문장으로 시작한다. 굵은 제목에 쓴 낱말이 바로 뒤 문장에 다시 나오면 제목을 지운다. 항목 이름이 꼭 필요하면(기능 목록, 위험 목록) 굵은 글씨와 콜론 없이 두 열 표로 정리한다. 표 머리글은 내용에 맞게 정한다(예: 기능 | 설명, 위험 | 대응).

| 고치기 전 | 고친 뒤 |
|---|---|
| - **응답 시간:** 평균 응답 시간이 120ms에서 80ms로 줄었다. | - 평균 응답 시간이 120ms에서 80ms로 줄었다. |
| - **로그 보관:** 접속 로그는 30일 동안 보관한다. | - 접속 로그는 30일 동안 보관한다. |

### 2. 기호로 문장 대신하기
화살표(→), 슬래시(/), 줄표(-)로 동사를 대신하지 않는다. 동사를 넣어 문장으로 쓴다. 문장을 나눌 때는 마침표나 쉼표를 쓴다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 빌드 → 테스트 → 배포 순서로 실행한다. | 빌드하고 테스트한 뒤 배포한다. |
| 실패 시 → 재시도, 3회 초과 → 중단 | 실패하면 다시 시도하고, 3회를 넘으면 중단한다. |

### 3. 의문형 소제목
소제목은 명사형으로 쓴다.

| 고치기 전 | 고친 뒤 |
|---|---|
| ## 왜 만들었나요? | ## 만든 이유 |
| ## 어떻게 설치하나요? | ## 설치 |

### 4. "X가 아니라 Y" 대비 구문
아무도 X라고 하지 않았는데 X를 부정하며 시작하면 Y만 쓴다. 범위를 밝히는 문장이 꼭 필요하면 "다루지 않는다"를 써서 사실로 적는다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 단순한 화면 모음이 아니라, 업무 흐름을 담은 포털이다. | 업무 흐름을 담은 포털이다. |
| 모든 인증 방식을 지원하려는 라이브러리는 아닙니다. 사내 SSO에 맞춰 만들었습니다. | 사내 SSO 인증만 지원합니다. 외부 OAuth 공급자 연동은 다루지 않습니다. |

### 5. 상투 표현과 군더더기
뜻을 더하지 않는 말은 지우고, 느낌 대신 원문이나 문맥에 있는 사실이나 숫자를 쓴다. 근거가 없으면 지우기만 한다.

| 고치기 전 | 고친 뒤 |
|---|---|
| ~하는 것이 중요합니다. | (지운다. 그 일을 하라는 문장으로 쓴다.) |
| 다양한 · 효율적으로 · 원활하게 · 손쉽게 · 강력한 | 원문 · 문맥에 있는 개수, 시간, 단계 수. 근거가 없으면 지운다. |
| ~를 통해 | ~로 · ~해서 |
| 결론적으로 · 요약하면 · 앞으로가 기대됩니다 | (지운다. 다음 할 일이나 사실을 쓴다.) |
| 도움이 되었기를 바랍니다 · 궁금한 점은 언제든 물어보세요 | (지운다.) |

항목 수는 실제 개수대로 쓴다. 셋을 맞추려고 항목을 늘리거나 합치지 않는다.

## 낱말 쓰임
| 낱말 | 규칙 | 고치기 전 | 고친 뒤 |
|---|---|---|---|
| 적는다 | 사람이 기록하는 행위에만 쓴다. | 이 장은 배포 절차를 적는다. | 이 장에서는 배포 절차를 설명한다. |
| 보인다 | 화면에 나타낸다는 뜻이면 "표시한다"로 쓴다. 사람이 실제로 보는 행위("운영자는 대시보드에서 상태를 볼 수 있다")는 그대로 둔다. | 실패하면 빨간 배너가 보인다. | 실패하면 빨간 배너를 표시한다. |
| …로 본다 | '간주' 뜻이면 "…로 처리한다"로 쓴다. 판정이 핵심이면 "…로 간주한다". | 30초 안에 응답이 없으면 실패로 본다. | 30초 안에 응답이 없으면 실패로 처리한다. |

## 빠른 점검
고친 뒤 다음 낱말을 찾아 다시 읽는다.
- "참고한다, 가리킨다, 대신한다, 보여 준다"의 주어가 사람 · 시스템이 아닌가
- "여기에 있다", "둔다"가 한 문단에 두 번 이상 나오는가
- "~은 ~이다"로 끝나는 문장이 영어 "is" 구문을 옮긴 것인가
- 영어 낱말에 풀이가 없거나, 장 · 절마다 처음 나올 때 풀이가 빠졌는가
- "적는다, 보인다, 본다"의 주어 · 뜻이 규칙과 맞는가
- 목록에 `**…:**` 또는 `**…**:`가 있는가, 그 낱말이 바로 뒤에 되풀이되는가
- →, /, - 기호가 동사 자리에 있는가
- 소제목이 "?"로 끝나는가
- "~가 아니라", "~는 아닙니다"로 시작하는 문장이 있는가
- 유형 5 표의 낱말이 있는가

## 흔한 실수
| 실수 | 바로잡는 법 |
|---|---|
| 고치다가 뜻이 바뀐다 | "필드는 ID를 가리킨다"를 "필드 값은 ID다"로 바꾸면 '참조'라는 뜻이 사라질 수 있다. 뜻이 달라지면 문장 구조를 바꾸고, 판단이 어려우면 그대로 두고 알린다. |
| 지나치게 고친다 | 자연스러운 정의 명사문, 사람이 보는 행위의 "본다", 시스템이 주어인 동작 문장은 고치지 않는다. |
| 목록을 모두 문단으로 바꾼다 | "AI 티 다섯 유형"의 유형 1은 굵은 제목과 콜론만 고친다. 순서나 나열이 있는 내용은 목록으로 둔다. |
| 코드 속 기호까지 고친다 | 코드 · 경로 · 명령의 `/`, `->`, 버전 범위 표기는 그대로 둔다. |
| 풀이를 ID 안에 넣는다 | "spec Requirement(요구사항 항목) 3.1"처럼 ID를 끊지 않는다. "spec Requirement 3.1(요구사항 항목 번호)"로 쓴다. |
